# TTS Service (文本发音变调与声音克隆服务)

**源码位置**: `services/tts/`
**框架**: `FastAPI`, `edge-tts`, `dashscope` (阿里云)
**网络角色**: 将 LLM 生成的字符流转为高保真度、高情感拟真音频流的搬运组。

## 核心架构功能

玩具能否让人感到是一个真实的“玩伴”，重点取决于声音流露出的感情以及音色带来的亲切感。
现已升级为**双引擎架构 (Dual Engine)**，入口统一处理 `GET /synthesize` 并根据网关传来的 `engine` 参数进行动态分发：

### 1. 微软 Edge-TTS (兜底免费引擎)
- **利用免费外部云 API 彻底瘦身**：绝大多数显卡资源已经被 Ollama 等大模型抢占，本地再跑一个包含复杂端到端生成音位的 TTS 模型必然会导致 OOM。
- 通过协议桥接，将文本发送至微软云端生成 MP3 并直接返回，不再依赖本地显卡资源去进行波形合成。

### 2. 阿里云 CosyVoice (高级人声与零样本克隆)
- **Zero-shot 声音克隆 (`POST /clone_voice`)**：新增对阿里云 DashScope 大模型的闭环对接。允许前端经过网关向本服务上传 3~10 秒的本地高质量录音（如爸爸妈妈的声音）。
- TTS 服务通过调用 `VoiceEnrollmentService.create_voice` 对音频提取声学包裹特征并立刻登记专属的 `Voice ID`。
- 合成时，服务捕获大模型本文，附带专有 `Voice ID` 向云端请求极高相似度的克隆发声，大幅提升幼教互动期间儿童对拟人化玩具的情感寄托。

## 关键微服务设计选型
- **无状态设计与配置透传化**：该微服务自身`不存任何数据库`，也不保存 `API Keys`。所有凭据（包括阿里云凭据）、音调、语速，均在合成瞬间由上游网关从其本地池中读出并插入请求头部 (Query/Form)。
- **智能拦截纠偏**：面对前端乱跳的错误语音代号（如选了 CosyVoice 但传入了 Edge-TTS 的 `zh-CN-` 参数），服务会在底层执行静默兼容性替换，保障无论发生什么都不会造成静音（Silence）崩溃。
