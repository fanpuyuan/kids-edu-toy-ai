# Gateway Service (总控网关层)

**源码位置**: `services/gateway/`
**框架**: `FastAPI`
**网络角色**: 唯一面向公网或硬件设备的接入点与配置保管者。

## 核心架构功能

### 1. WebSocket 全双工流通信
这是网关的核心对用户业务职责：
- 负责维持与儿童玩具硬件端（或前端语音交互面板）的长时间音频/文本双向连接。
- 采用生产-消费模式并发机制，接收到用麦克风输入的原始音频小块后即可转推给后端 ASR。
- 等待架构内微服务处理完成，并从 TTS 收到片段语音后，立刻以 WebSocket 形式流式推回硬件播放，**将首字节延迟（TTFB）降至最低**。

### 2. 全局会话状态与配置维护 (新进驻)
为了降低代码耦合度与提高安全性：
- 网关拥有自己专属的本地轻量级数据库 **SQLite (`gateway.db`)**。
- 它集中化管理所有微服务的**全局核心配置**：API 秘钥 (Ollama/DashScope)、选择的对话大模型、激活的 TTS 引擎 (Edge-TTS 或 CosyVoice)、以及专属于用户的声音克隆 Voice ID。
- **参数透传**：每次向后方的 Brain、TTS 服务发起请求时，网关会自动丛 `gateway.db` 读取到最新的 Token 或语速设定，动态地将这些参数注入到底层 HTTP 请求中。**前端调参、全局瞬时生效，底层微服务从此变为无状态(Stateless)。**

### 3. 反向路由与媒体数据代理 (Proxy Node)
网关对前端所有的控制面板和特殊请求起着路由器的作用：
- 接管前端发来的大文件上传请求 (`/upload_doc`) 和清除指令 (`/clear_docs`)，将其代理到后端的 RAG Service 持久化存储知识。
- **新增**：接管前端发来的声音克隆录音文件请求 (`/clone_voice`)，将其透传代理到后端的 TTS Service 进行大模型零样本音色注册。

### 4. LangGraph 进度与安全监控 (Background Tasks)
由于我们接驳了对 Ollama 的管理台：
- 使用 FastAPI 跑后台任务轮询 `/api/pull` 模型拉取状况，暴露 HTTP 端点，借由此给前端提供进度条同步渲染。
- 判断并防止在未下载完大模型时，物理玩具盲目发起的调用乱流。

## 与旧版单体架构的对比
该部分由之前包含整个大模型推导的单体代码剥离而来。现在的 Gateway 容错性极高：由于去除了 GPU 与大模型模块（只使用 pure Python web modules），即使底层任何 AI 模型崩溃断线，网关依然稳定生存，且能平滑地下发“系统升级中哦”的网络错误托底童声音频。
