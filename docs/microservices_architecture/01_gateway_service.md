# Gateway Service (总控网关层)

**源码位置**: `services/gateway/`
**框架**: `FastAPI`
**网络角色**: 唯一面向公网或硬件设备的接入点。

## 核心架构功能

### 1. WebSocket 全双工流通信
这是网关的核心业务职责：
- 负责维持与儿童玩具硬件端（或前端语音模拟面板）的长时间音频/文本双向连接。
- 采用生产-消费模式并发机制，接收到用户的原始音频小块后立刻切片并组装，随即转推给后端的 ASR 节点。
- 等待后端大模型流式生成结果，并从 TTS 收到片段语音后，立刻以 WebSocket 形式流式推回硬件设备播放，**将首字节延迟（TTFB）降至最低**。

### 2. 反向路由HTTP代理 (Proxy Node)
网关对前端所有的控制面板也起着路由器的作用：
- 接管前端发来的大文件上传请求 (`/upload_doc`)，为了避免 OOM 或保存状态，它将其内存流代理到后端的 RAG Service。
- 接管前对小主人系统记忆的读写请求 (`/memory/*`)，以同样的透传模式路由给 RAG 服务的记忆控制器。

### 3. 全局会话状态与配置维护
玩具随时可能脱网，网关负责存储当前的临时设定：
- 内存中持有着当前选中的大语言模型类型。
- 维护着前端下发的声音特色配置（例如音色 `voice` 和语速 `rate`）。
- **参数透传**：每次向后端的 Brain 发送大语言模型请求，或向后端的 TTS 发送语音合成请求时，该服务会把当前所有动态参数附带至 Header 或者 Query Param，实现**前端调参、全局生效**。

### 4. LangGraph 进度与安全监控 (Background Tasks)
由于我们接驳了对 Ollama 的管理台：
- 使用 FastAPI 跑后台挂载任务轮询 `/api/pull` 模型拉取状况，对外暴露 HTTP 端点，借由此实现进度条同步渲染。
- 判断并防止在未拉取完模型时硬件触发的大模型调用雪崩。

## 与旧版单体架构的对比
该部分由之前包含整个大模型推导的 `api.py` 完整拆解分离。现在的单向 Gateway 容错性极高：由于去除了所有 GPU 以及机器学习轮子的重度依赖（只使用 pure python web modules），即使底层大模型崩溃了，网关也依然能够稳定存在，平滑地回复给玩具终端一段“我还没想好哦”的网络错误托底音频。
