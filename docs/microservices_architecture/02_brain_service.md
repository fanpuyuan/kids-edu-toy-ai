# Brain Service (大脑思维与逻辑流层)

**源码位置**: `services/brain/`
**框架**: `FastAPI`, `LangGraph 1.2 LTS` (LangChain)
**网络角色**: 这个项目的核心大脑，所有业务逻辑状态机都在此处运转，它负责驱动推理模型和工具网络，但不与用户终端发生直接物理连接。

## 核心架构功能

### Agent 节点拓扑与状态流转 (StateGraph)
本次重构彻底抛弃了脆弱不可测的 `AgentExecutor` 与旧版 `LLMChain` ，转为使用最新的图模型 **StateGraph** 进行严格路由调度：

1. **`analyze_intent` 节点 (起点)** 
   - 这是入口分析节点。每当网关传过来一段用户说的话，它首先调动一次轻量级的大语言模型做意图分类：判断当前这句话是不是一个寻求特定知识或是需要故事库的请求（如“黑洞是什么？”与“讲个《小猪佩奇》的故事”），还是这只是一句短时问候闲聊？

2. **`retrieve` 节点 (可选流向/按需切入)**
   - 它是架构图中的“找书员”。仅当上一步将意图打标成了 `qa` 或 `story`，此处的边 (Edge) 就会跳转到它。
   - 它的工作是：带上用户的输入，跨服务去调用 HTTP 到内网 `rag-service:8003/retrieve`。拿到包含文献溯源的 `Citation` 上下文数据后，压入系统临时状态缓存。

3. **`generate` 节点 (终点流式合成与自助记忆提取)**
   - 这是最终合成对话结果的总出口。无论上游走的是闲聊还是查找，最终全部落点于此。
   - **双网/多模型引擎路由 (新增)**：彻底摆脱了此前仅锁死本地 Ollama 的限制。该节点在运行时，会读取上游网关传来的 `config` 字典，动态组装 LangChain 实例，决定本次是调用本地 Ollama 还是携带 API Key 请求云端闭源模型（如 DeepSeek、GLM 等）。
   - **全局记忆同步**：它首先进行远程调用，去拉取 `rag-service` 中的纯文本记忆体系：包含最重要的死规则 (`SYSTEM.md`)，小主人的档案 (`FAMILY.md`)，以及历史的上下文小结 (`SNAPSHOT.md`)。
   - **自动记忆提取拦截器 (Auto-Memory Extractor)**：在底层 Prompt 中植入了隐藏任务。如果大模型在聊天时推理出小主人说出了新的喜好设定（如“我不爱吃胡萝卜”），生成流的末尾会带有 `<UPDATE_MEMORY>` 标签。程序内部使用正则拦截剥除该标签免遭 TTS 偷读出来，并自动往回发送给 RAG Service 记入 `SNAPSHOT` 中。
   - **流式返回**：完成所有处理后，实现打字机效果逐块传回给外层网关应用层。

## 架构隔离优势
由于逻辑推理环节极度依赖外部因素（显存打满 OOM、云端 API 重试、复杂 Prompt 调优失败导致结构输出崩溃），Brain 服务容器由于是纯内网独立提供，它完全有时间独立阻塞或者优雅重试挂起，并在异常时由网关平滑托底返回，这极大改善了系统的稳定性。
